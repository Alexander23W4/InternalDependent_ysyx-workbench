-> 时序优化：
| 延迟来源                                   | 描述                          | 相对大小 / 排名 | 典型范围                   | 备注                                       |
| -------------------------------------- | --------------------------- | --------- | ---------------------- | ---------------------------------------- |
| **互连 / 金属线 (Wire/Metal)**              | 信号在芯片上从一个模块走到另一个模块          | 最大 / 很大   | 几 ps ~ 几百 ps（长线 + 高扇出） | 现代工艺下常成为关键路径瓶颈，尤其是低扇出 → 高层metal加粗可降低RC延迟 |
| **逻辑门 (AND/OR/XOR/INV 等组合逻辑)**         | 标准单元逻辑                      | 中等        | 10~50 ps（单级门）          | 多级组合逻辑累加，会快速成为关键路径                       |
| **MUX / 条件选择逻辑**                       | 2:1 MUX、n:1 MUX             | 中等偏高      | 20~60 ps               | 层数太多会累加，和逻辑门一样                           |
| **寄存器 / FF / Latch**                   | 时序逻辑，寄存器采样延迟 + setup + hold | 中等        | 30~100 ps              | 会增加路径延迟，但寄存器可切分长组合逻辑 → 流水线优化             |
| **跨层 / 缓冲器 (Buffer / Inverter chain)** | 用于驱动大扇出或长线                  | 中等偏低      | 10~40 ps               | 有时候为了驱动fanout必须插入，增加面积，但可以降低总路径RC延迟      |
| **门扇出过大**                              | 一个逻辑门驱动太多负载                 | 高         | 取决负载电容                 | 扇出太大 → 上下游延迟增加                           |
| **Latch vs FF**                        | Latch 有时序敏感窗口，可减少路径层数       | 中等        | 视clocking方案            | 使用透明latch可以节省寄存器数，但控制复杂                  |

synthesizer会在某些情况下保护逻辑而在性能方面做出让步（parallel->serial等):
注意如果是并行逻辑， 必须确保这些情况完全并行， 不能交叉或者嵌套递归等
-> 多路or写冲突
1. 多驱动冲突 → 串行优先级编码器
text
你的for循环：
for(i=0;i<4;i++) if(in[i]) out = i;

综合器：4路写冲突！→ **4级串行优先级**
性能：2.1ns → **3.8ns** (+80%)
2. 不完整case/if → 意外锁存器
verilog
always @(*) begin
  if(cond) out = 1;  // 漏else！
end
text
综合器：保持上次值 → **锁存器**（组合变时序！）
性能：组合2ns → **锁存器8ns** (+300%)
3. 混合阻塞/非阻塞赋值 → 锁存器+竞争
verilog
always @(posedge clk) begin
  a = b;      // 阻塞
  c <= d;     // 非阻塞
end
text
综合器：逻辑混乱 → **锁存器+多周期**
性能：单周期 → **多周期错误**
4. 敏感列表不完整 → 仿真/硬件不一致
verilog
always @(a) out = a | b;  // 漏b！
text
仿真：b变out不变
硬件：b变out变（锁死寄存器！）
综合器：**插入锁存器保证硬件正确**
5. 三态逻辑 → 总线保持器
verilog
assign bus = en ? data : 1'bz;
text
综合器：不支持三态 → **MUX+保持器**
LUT：8 → **16 LUT** (+100%)
6. 动态循环边界 → 状态机展开
verilog
for(i=0; i<len; i++)  // len运行时变！
text
综合器：len最大值状态机
性能：并行 → **串行N周期**

结构描述（YSYX高手）：
时钟：0ns    5ns    10ns   15ns   20ns   25ns
     ┌──────┼──────┼──────┼──────┼──────┼
IF   │ pc=0 │ pc=4 │ pc=8 │ pc=C │ ...  │
     │inst0 │inst1 │inst2 │inst3 │     │
     ├──────┼──────┼──────┼──────┼──────┼
ID   │      │inst0 │inst1 │inst2 │inst3 │
     │ rs10 │ rs11 │ rs12 │ rs13 │     │
     ├──────┼──────┼──────┼──────┼──────┼
EX   │      │      │inst0 │inst1 │inst2 │
     │      │      │add=8 │add=9│     │
     ├──────┼──────┼──────┼──────┼──────┼
MEM  │      │      │      │add=8 │add=9│
WB   │      │      │      │      │add=8 │

每个格子=15ns，流水线并行 → 250MHz
用5级流水线手工打断所有长路径，时序收敛。  inst pipeline: 

1. **约束降低频率**：200MHz→180MHz（偷懒）
2. **综合优化**：retiming寄存器插入（自动70%）
3. **结构流水线**：手工打断关键路径（YSYX核心）
4. **Floorplan**：关键模块固定区域
5. **物理优化**：手工移动违例cell

结构描述强制每15ns保存中间结果，综合器只能顺着走！

3. **结构流水线（手工打断）**
   ├─ 5级流水线IF-ID-EX-MEM-WB  ← YSYX基础
   ├─ **指令字段并行解码**      ← 你书上看到的！
   ├─ 寄存器文件双端口读         ← 并行rs1+rs2
   └─ 多ALU并行执行

流水线冲刷机制：
实际运行时：
时钟0ns：IF取inst0=beq x1,label  (pc=pc0)
时钟5ns：IF取inst1=???           (pc=pc4)  ← 已经开始了！
时钟10ns：ID发现是beq跳转！

这时两种情况：
- 不跳转：inst1是对的，继续流水
- 跳转：冲刷错误指令，重取label地址
