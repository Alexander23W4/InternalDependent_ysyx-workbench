从用户程序出发: 以dummy为例
传入 make ARCH=riscv32e-npc ALL=dummy run
封装Makefile.dummy 

传递
NAME = dummy  SRCS = tests/dummy.c MAKECMDGOALS

引出AM_Makefile  执行 make -s -f Make.dummy ARCH=$(ARCH) $(MAKECMDGOALS)  (make -s -f Make.dummy ARCH=minirv-npc run)


-include $(ARCH).mk  
$(ARCH).mk -> ISA.mk  PLATFORM.mk

封装$(IMAGE).elf  文件 编译归档链接(flag + 规则)  
am klib -> .a   guest -> .o 
am.a klib.a guest.o 链接形成 $(IMAGE).elf

对IMAGE进行 插入ARGS, 分身操作后, 执行 make指令传给 cpu层

nemu为例, build.mk -> $(BINARY)   native.mk -> $(BINARY) $(ARGS) $(IMG)



几个Makefile文件的结构: 

AM层:

AM_Makefile: 
Check Config   
Setup 编译整合所需变量(ISA, PLATFORM, DST_DIR, IMAGE)  
Compiler & Flags & Compilation Rules
Miscellaneous

ARCH.mk(如riscv32-nemu.mk): 
将所有ARCH-specific的flags 和 files 包含进去, 补充关于ARCH的配置给编译器
比如: -melf32lriscv：告诉链接器使用 ELF 32 位小端 RISC-V 的输出格式

ISA.mk(如riscv.mk)
补充有关ISA的编译配置

PLATFORM.mk(如nemu.mk)
不同编译配置和平台配置
定义AM层的MAKECMDGOALS规则

CPU层(NEMU为例):
Makefile build.mk filelist.mk  3者共同组成一个完整的 CONFIG-ITEMS-RULES Makefile
