SYSTEMIC UNDERSTANDING:
🔹 Runtime Environment（运行时环境）
指：
程序在“运行时”所依赖的整体环境
它包括：
操作系统
进程模型
内存布局
栈结构
加载器（loader）
动态链接器
libc
运行时库
系统调用接口
以及 ABI 规则

🔹 ABI（Application Binary Interface）
ABI 是：
二进制层面的接口规范
它规定：
函数调用怎么传参
返回值放哪里
寄存器如何使用
栈如何增长
数据类型大小
对齐规则
调用约定（calling convention）
可执行文件格式（例如 ELF）


例如在 RISC-V Linux 上：

ABI 会规定：
参数放在：
a0–a7 寄存器

返回值：
a0
栈向下增长
结构体对齐方式
ELF 格式

而 runtime environment 还包括：
Linux 内核
动态链接器 ld.so
glibc
启动代码 _start
程序入口流程


ABI 有两种层次
1. 用户态 ABI (compiler decided)
解决
函数调用规则
数据布局
寄存器分配

2. 系统调用 ABI (printf interrupt... )  customer code (user mode) could not decided
解决
用户如何请求内核服务
内核如何接收参数
内核如何返回结果
这部分：是 OS 必须定义的



OS CRITICAL COMPONENT:

CPU 上电后会做一件极其简单但关键的事：
PC（程序计数器） = 固定地址
这个地址在不同架构是硬编码在 CPU 设计里的。
this addr is projected to BIOS/UEFI (in flash mem) 

->BIOS/UEFI 
BIOS 做的事情：
初始化内存（RAM）
初始化设备
找启动设备（硬盘）
加载 bootloader

->Bootloader
; 从磁盘读 kernel 到内存
; 跳转到 kernel entry
jmp kernel_main

->CPU 模式切换
real mode → protected mode → long mode（x86）
必须做：
开启分页（paging）
设置段寄存器
初始化栈

->内存管理
物理内存管理
虚拟内存管理
内核堆

->Process & task 进程&任务系统
上下文切换  调度器

->中断系统（Interrupt / Trap）
核心作用：
CPU 和外界交互

你需要：
（1）IDT（中断描述符表）
interrupt number → handler
（2）中断处理函数
void timer_handler();
void keyboard_handler();
（3）系统调用（Syscall）
用户态 → 内核态：
int 0x80
或现代：
syscall 指令

->驱动（Drivers）

最基础必须有：
（1）定时器（Timer）
用于调度
（2）串口 / 控制台
输出日志
（3）键盘（可选）
