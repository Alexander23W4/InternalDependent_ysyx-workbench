⭐: 有关我基于AM开发的用户程序怎么引用头文件的问题: 

几个疑问: 怎么使用int8_t

关键理解: 声明(.h) 和 实现(klib, glibc) 的分离

1. 头文件（.h）由编译器提供
stdint.h、stdlib.h、stdio.h 等头文件是 编译器安装时自带的，它们只包含类型定义、宏和函数声明。

这些头文件不包含任何函数的实现代码，因此不需要 klib 提供。

无论在 native 还是 riscv32-nemu 环境下，编译器都会在它的系统头文件目录中查找这些 .h 文件。

2. 库函数实现（.a 或 .so）由 klib 或 glibc 提供
malloc、printf 等函数的实际机器码，在 native 下由 glibc（动态库 libc.so.6）提供。

在 riscv32-nemu 等裸机环境下，由你的 klib（静态库 klib-$(ARCH).a）提供。

链接器在链接阶段决定使用哪个实现。



#include 是给编译器看的“说明书”，而库实现是给链接器提供的“机器码”。
所以按理来说, ⭐ 无论用的是逻辑的库函数(klib) 还是标准库函数 (glibc), 都需要#include 引用对应的函数声明

⭐: 汇编器 和 汇编阶段 起到找库函数实现的作用
编译器查找头文件：通过 -I 和系统默认的 include 路径找 .h 文件。
链接器查找库文件：通过 -L 和系统默认的 lib 路径找 .a 或 .so 库。

⭐: 默认的 include 路径 和 lib 路径 在哪里? 然后再明确 PATH 的作用!

PATH：是操作系统用来找可执行文件（.exe）的，比如你在终端输入 gcc，系统会去 PATH 里列出的目录找 gcc 这个程序。
编译器搜索路径：是编译器自己内置的，用来找头文件（.h）和库文件（.a/.so）。
