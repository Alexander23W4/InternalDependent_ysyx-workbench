第1层：芯片识别与调试支持（Device + DFP）
逻辑： 告诉Keil“我的芯片是哪个型号”，并让Keil拥有该芯片的硬件信息（寄存器地址、Flash大小、内核类型等）。

Device 选择：在 Options for Target → Device 里选 STM32F407ZGT6。
    这一步决定了编译器使用的预定义宏（如 STM32F40_41xxx）。
DFP（Device Family Pack）：这是芯片的“硬件数据库”，包含芯片识别文件、
    CMSIS核心头文件、Flash烧录算法、SVD调试描述文件等。必须安装，否则Keil不认识芯片。



第2层：启动与硬件初始化（Startup + SystemInit）
逻辑： 芯片上电后，C语言运行环境尚未建立。启动文件（.s）负责设置栈指针、调用 SystemInit() 配置时钟，
    然后跳转到 main()。这是C程序运行的“前置条件”。

启动文件 startup_stm32f407xx.s：由汇编编写，是芯片复位后执行的第一段代码。
system_stm32f4xx.c：包含 SystemInit() 函数，在进入 main() 前被启动文件调用，
    用于配置系统时钟（默认使用HSI或HSE，具体取决于芯片和你的配置）。


第3层：标准库与驱动（StdPeriph_Driver）


第4层：用户应用与配置文件（User）
逻辑： 这是最终你写代码的地方。
    但你的代码需要依赖两个关键配置——告诉标准库“这个芯片要启用哪些外设”的配置文件，以及你自己的 main.c。

stm32f4xx_conf.h：标准库的“总开关”，用于启用或禁用特定外设的驱动头文件，并包含断言检查配置。
    你在 main.c 里 #include "stm32f4xx.h" 后，这个文件会被自动包含。
main.c：你的应用程序入口，包含 main() 函数和你的业务逻辑。
stm32f4xx_it.c：中断服务函数存放处（虽然你可以自己写，但标准库模板提供了空壳，方便你填入中断处理代码）。



MyProject/

⭐ Cortex-M 嵌入式 CPU架构

CMSIS 是 Cortex Microcontroller Software Interface Standard 的缩写，中文意为“Cortex 微控制器软件接口标准”。

简单来说，它是 ARM 公司为所有 Cortex-M 系列处理器定义的一套统一的软件抽象层，目的是让不同的芯片厂商（如 ST、NXP、TI 等）
    在使用相同的 Cortex-M 内核时，能提供一套兼容的软件接口。
 
CMSIS 的组成
组件	作用	对应文件
CMSIS-CORE	内核寄存器定义、NVIC（中断控制器）、SysTick（系统定时器）、MPU（内存保护单元）等的标准接口	core_cm4.h、core_cmFunc.h 等
CMSIS-DSP	DSP 指令的数学库（FFT、滤波、矩阵运算等）	arm_math.h 等
CMSIS-RTOS	操作系统抽象层，让 RTOS 可以统一调用内核功能	cmsis_os.h
CMSIS-Driver	外设驱动的统一接口（由芯片厂商实现）	—
CMSIS-SVD	芯片寄存器描述的 XML 文件，供调试器使用	.svd 文件


CMSIS 和 DFP 的关系
概念	                                关系
CMSIS	                        ARM 定义的软件接口标准，是“通用规则”
DFP（Device Family Pack）	芯片厂商（如 ST）把 CMSIS 核心文件 + 芯片特定定义（Flash 算法、SVD 等）打包成的一个“芯片支持包”
你的工程	                    通过 DFP 获取 CMSIS 核心文件，通过标准库（SPL）获取外设驱动

CMSIS这些文件和标准库文件在同一层, 
    比如 core_cm4.h 包含 NVIC_SetPriority(USART1_IRQn, 0)这些函数



    ARM 统一了什么	                                            ARM 没统一什么
内核操作（中断使能、NVIC、SysTick、堆栈指针操作）	            外设寄存器地址
内核寄存器访问方式（__disable_irq()）	                    外设寄存器的位域定义（GPIO 的 MODER、OTYPER 在各厂商可能不同）
系统控制空间基地址（0xE000E000）	                            外设 API 命名
中断号命名规范（USART1_IRQn 由芯片厂商定义）	        外设初始化结构体（GPIO_InitTypeDef 是 ST 的写法，NXP 可能是 gpio_pin_config_t）
CMSIS-CORE 头文件（core_cm4.h）	                        标准外设库（SPL）或 HAL 库


⭐⭐: 链接脚本(.ld) [新概念]
函数的先后顺序是谁规定的呢, 谁来告诉编译器这个逻辑顺序呢???  是链接脚本

链接脚本是编译器/链接器决定函数放哪里的“总指挥”。
它在 Keil 中通常是一个 .sct 文件（ARM 语法）或 .ld 文件（GCC 语法），由芯片厂商提供，你也可以自己修改。

Keil 根据你选择的芯片型号和工程配置，自动生成一个标准的 .sct 链接脚本，然后把它交给链接器使用。
